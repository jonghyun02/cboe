# 음원 분리 단계를 빼는 설계 (요약)

**상태: 설계안이다. 아직 구현하지 않았다**(2026-11-11 작성). 지금 코드는 음원 분리 단계가 있는 그대로다.

수치는 실사 장편 영화 한 편의 앞 30분을 지금 방식으로 돌려 저장해 둔 점수와 세기로 센 어림이다. 모델은 다시 돌리지 않았다. 정답 SDH 자막이 없어서 "어느 쪽이 맞다"는 말은 하지 않는다. 수가 어떻게 바뀌는지만 적는다.

## 1. 무엇을 하려는가

지금은 영화 소리를 대사·음악·효과음 세 트랙으로 나눈 뒤(Bandit v2) 트랙마다 따로 분석한다. 설계는 이 단계를 없애고, 모든 단계가 나누지 않은 원본 소리(mix) 하나만 읽게 한다.

배경은 셋이다.

- 소리 검출 모델(PretrainedSED)은 AudioSet 의 프레임 단위 라벨로 학습했다(모델 저장소의 설명). AudioSet 의 소리는 나누지 않은 소리다. 그래서 나눈 효과음 트랙은 학습 자료와 다른 꼴의 입력이다.
- 지금 방식의 효과음 후보 301개 가운데 216개는 효과음 트랙의 세기 뜀으로만 찾은 것이다. 그 216개 가운데 110개가 대사와 겹친다(대사가 있는 시간은 전체의 30%).
- 분리는 재어 둔 단계 가운데 가장 오래 걸린다. 영화 30분에 1062.0초다(받아쓰기 324.1초, 소리 검출 125.0초, 음악 76.2초).

## 2. 단계별로 바뀌는 것

| 단계 | 지금 | 설계 |
|---|---|---|
| separate (음원 분리) | Bandit v2 로 세 트랙을 만든다 | 없앤다 |
| ingest (소리 뽑기) | 원본 48 kHz 와 16 kHz | 원본 16 kHz 하나(`mix_16k.wav`) |
| sed (소리 검출 점수) | 효과음·원본·음악 세 트랙에 한 번씩, 트랙별 세기 | 원본에 한 번, 원본 세기 |
| asr (받아쓰기) | 대사 트랙을 받아쓴다 | 원본을 받아쓴다 |
| sfx (효과음 후보) | 효과음 트랙의 점수와 세기 뜀 | 원본 점수는 늘 쓴다. 세기 뜀은 말이 없는 곳에서만 쓴다. 말과 겹친 후보에는 표시(`in_speech`)를 단다 |
| music (음악 후보) | 음악 트랙의 점수. 시작을 세기 곡선으로 다듬는다 | 원본의 Music(음악) 점수. 시작은 점수 시각 그대로 둔다 |
| agent (재확인 도구) | 트랙을 골라 다시 검출하고 듣는다 | 원본만 쓴다 |
| 검수 화면 시간줄 | 트랙 세 개의 세기 곡선 | 원본 세기 곡선 하나 |
| 옛 작업 폴더 | — | 자동으로 다시 분석하지 않는다. 분리한 트랙으로 만든 결과라는 표시만 한다 |

## 3. 규칙이 바뀌는 네 곳

원본 소리의 세기는 대사가 지배한다. 그래서 세기를 쓰는 규칙은 말이 없는 곳에서만 쓴다.

1. **말이 있는 곳을 아는 방법.** 받아쓰기에 기대지 않는다. 소리 검출 점수에서 말 갈래 10종 가운데 하나라도 0.3 이상인 시간을 "말 가면"으로 쓴다(효과음). 음악 쪽은 웃음·비명·울음 같은 목소리 종류까지 더한 "목소리 가면"을 쓴다.
2. **말 가면 안에서는 세기 뜀을 재지 않는다**(값 0). 그래서 세기만으로 만드는 '알 수 없는 소리' 후보와 '갑자기 큰 소리' 추천이 말 안에서는 나오지 않는다.
3. **'큰 소리' 문턱(백분위)** 은 세기 규칙이 켜진 프레임에서만 센다.
4. **음악 시작**을 세기 곡선으로 다듬지 않는다.

바꾸지 않는 것: 음악 문턱(0.25), 음악 멈춤 규칙, 재확인 대기열의 차례.

## 4. 수가 어떻게 바뀌나 (영화 한 편의 앞 30분)

### 모델 없이 센 것

|---|---|---|
| 효과음 후보 | 301 | 225 |
| 그 가운데 알 수 없는 소리 | 75 | 12 |
| 대사와 겹친 후보 | 146 | 81 |
| 그 가운데 사건 소리(event) | 59 | 8 |

| 규칙만의 추천: 넣기(include) / 확인(check) / 빼기(exclude) | 79 / 218 / 4 | 25 / 199 / 1 |
| 지금 넣기 추천 79개 가운데 새 목록에도 후보가 있는 것(시작 ±1초) | — | 28 |
| 대본의 소리 단서 21개 가운데 후보가 붙는 것 | 11 (같은 종류 8 + 이름 없는 소리 3) | 10 (같은 종류 10). 지금과 같은 단서는 8개 |
| 음악 구간 | 16개 480.4초 | 12개 339.0초 |

'대사와 겹침'의 기준은 분리한 대사 트랙의 세기다. 참값이 아니라 어림이다. 음악 후보에서 분위기 바뀜(지금 3개)은 뺐다. 분위기 모델을 돌려야 나온다. 설계대로 하면 세기 규칙이 꺼지는 시간은 951.9초(30분의 52.9%)다.

같은 영화 전체를 원본 소리로 받아쓴 결과가 있어서, 그 앞 30분으로 셌다(옛 코드, 이름 힌트 없음 — 어림이다).

|---|---|---|

| 대본 줄: 다르게 들림(differs) | 67 | 69 |
| 대본 줄: 못 맞춰 어림 시각에 놓음(unheard) | 36 | 46 |

### 아직 재지 못한 것

- 음악의 분위기와 악기(분위기 모델 AST 를 원본에 돌려야 안다), 음악 추천 수.
- 초안 배치의 칸 수와 위반 수.
- sed·asr·music 단계가 걸리는 시간. 확실한 것은 분리 단계 1062.0초가 없어진다는 것뿐이다.
- 정답이 있어야 아는 것: 말과 겹친 큰 소리 가운데 몇 개가 자막에 들어갈 소리인가, 소리 첫 프레임의 오차, 문턱값.

## 5. 잃는 것

큰 것부터 적는다.

1. **말과 겹친 효과음.** 말과 겹친 소리는 종류 점수가 문턱을 넘어 시작으로 잡힐 때만 후보가 된다. 일반 충격음(Generic impact sounds)처럼 혼자서는 시작을 내지 못하는 종류는 점수가 높아도 후보가 되지 않는다. 지금 방식이 '갑자기 큰 소리'로 넣자고 추천하던 70개 가운데 46개는 새 목록에 후보로도 없다. 대사와 겹친 사건 소리 후보는 59 → 8개, 넣기 추천은 79 → 25개다. 빠진 소리는 작가가 '+ 넣기'로 직접 넣어야 한다. 빠진 후보가 진짜 소리였는지, 분리가 만든 찌꺼기였는지는 정답이 없어 모른다. 되찾는 쉬운 길은 찾지 못했다.
2. **말 밖의 소리도 준다.** 세기 뜀으로만 찾던 후보가 216 → 55개다. 지금 후보 301개 가운데 166개는 새 후보가 ±1초 안에 없다.
3. **음악.** 찾는 시간이 480.4초 → 339.0초로 준다. 지금 구간 16개 가운데 6개가 통째로 빠진다. 말 밑에 깔린 배경 음악과 작은 음악을 놓칠 수 있다. 소리로 찾던 '[음악이 멈춘다]' 후보는 4 → 0개다.
4. **음악 시작 시각.** 새 시작 12개 가운데 7개가 지금 방식의 시각과 0.1초 넘게 다르다(중앙값 0.145초, 최대 0.57초).
5. **정렬.** 어림 시각으로 놓이는 대본 줄이 36 → 46줄로 는다.
6. **검수 화면과 도구.** 트랙별 세기 곡선이 원본 곡선 하나가 된다. 재확인 도구의 효과음 트랙 재검출과 듣기가 없어진다.
7. **옛 작업 폴더의 작가 결정.** 옛 폴더를 처음부터 다시 분석하면 후보의 시각이 바뀐다. 결정을 붙이는 열쇠가 그대로인 후보는 효과음 300개 가운데 44개, 음악 54개 가운데 5개뿐이다.
8. **한계.** 잰 것은 한 작품의 30분이고 정답이 없다. 문턱 숫자는 그대로 두지만, 원본 소리에서는 같은 민감도가 아니다.

## 6. 구현 차례

묶음은 넷이다. 1차 셋을 함께 하고, 그것이 합쳐진 뒤 2차를 한다. 1차만 합쳐진 상태에서도 전체 시험은 통과해야 한다. 묶음 사이의 약속(파일 형식, 함수 이름)은 14개다.

| 묶음 | 하는 일 | 주요 파일 |
|---|---|---|
| B. 검출 (1차) | 원본에 한 번만 도는 소리 검출, 말 가면, 효과음 후보 | `cboe/stages/sed.py`, `sfx.py`, `align.py` |
| C. 음악 · 받아쓰기 (1차) | 원본 Music 점수로 음악 구간, 원본 받아쓰기 | `cboe/stages/music.py`, `asr.py` |
| D. 검수 화면 · 재확인 도구 · 문서 (1차) | 원본 곡선 하나, 원본만 쓰는 도구, 문서 | `cboe/agent_tools.py`, `cboe/server/`, `README.md`·`USAGE.md`·`DESIGN.md` |
| A. 배관 · 설치 · 도구 (2차) | 분리 단계 삭제, 단계 목록, 옛 폴더 표시 | `cboe/pipeline.py`, `cboe/stages/separate.py`(삭제), `tools/` |

## 7. 구현 전에 정할 것

1. **옛 작업 폴더를 새 방식으로 다시 분석할지.** 코드는 자동으로 다시 분석하지 않는다. '처음부터 다시'를 고르면 효과음·음악 결정 대부분이 붙지 않는다.
2. **디스크에서 지울지.** Bandit 가중치(446.7 MB)와 옛 폴더의 분리 소리 파일(30분에 691.2 MB).
3. **발표 덱의 5.2(음원 분리) 장.** 첫 화면 README 표의 '덱' 칸이 가리키는 장이다.
4. **정답 구간을 만들지.** 작가가 정한 SDH 정답(효과음·음악·시작 시각)이 있어야 5절의 "모른다"를 잴 수 있다. 가장 먼저 잴 것은 말과 겹친 큰 소리 46개 가운데 몇 개가 자막에 들어갈 소리인가다. 없으면 문턱은 지금 값으로 둔다.

## 8. 검토 기록

설계는 코드와 결과 두 관점에서 검토했다. 1차 검토의 지적 16개는 모두 다시 확인했고 틀린 지적은 없었다. 대부분 설계에 반영해 2판을 만들었고, 일부는 선택지와 까닭만 적거나 검토의 제안과 다른 길로 고쳤다. 2판을 다시 검토한 결과는 두 관점 모두 통과였고, 작은 지적 12개가 구현 때 처리할 것으로 남았다. 그 가운데 눈여겨볼 것은 넷이다.

- 말과 겹친 후보(`in_speech`)를 작가가 검수 화면에서 알아볼 표시가 없다.
- 받아쓰기 입력이 바뀌면 대사 줄의 시작 시각도 바뀐다. 고친 뒤 잴 목록에 이 값이 없다.
- 분위기 모델에 말과 효과음이 섞인 원본을 넣게 된다. 그 영향이 '잃는 것'에 빠져 있다.
- 설계의 파일·줄 목록은 구조 개편 7차 전의 코드 기준이다. 7차가 더한 코드에서 분리 트랙에 기대는 곳을 다시 찾아야 한다.

전체 설계(결정 17개, 900여 줄)는 측정 스크립트와 함께 저장소 밖에 있다. 이 문서는 그 요약이다.
